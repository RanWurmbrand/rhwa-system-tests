## 2. Summary

The SBR operator renders, owns, and reconciles a per-config `NetworkPolicy`
(`sbr-agent-<sbrcName>`) for the agent DaemonSet pods: ingress is restricted to
the two metrics ports and scoped to namespaces labeled `metrics: enabled`,
egress is deliberately left unrestricted, and the operator warns when the
`openshift-monitoring` namespace lacks the required label.

## 3. Scope

- **In scope**:
  - Automatic rendering and application of the `sbr-agent-<sbrcName>`
    `NetworkPolicy` when a `StorageBasedRemediationConfig` is created.
  - Controller ownership linkage to the owning `StorageBasedRemediationConfig`
    CR.
  - Correctness of the ingress rule: exactly the two metrics ports
    (controller-runtime's `8080` and the agent's own `8082`), peer restricted
    to namespaces carrying `metrics: enabled`, no `podSelector`/`ipBlock`
    fallback.
  - Correctness of the egress rule: intentionally unrestricted (allow-all),
    by design — the shared-storage backend's endpoints, ports and IP ranges
    vary by provisioner and are not known to the operator.
  - Detection and recovery from `NetworkPolicy` deletion, and from a manually
    widened ingress rule.
  - The `MetricsNamespaceLabelMissing` Warning event the operator emits on
    the `StorageBasedRemediationConfig` when `openshift-monitoring` lacks the
    metrics label.

- **Out of scope**:
  - Validating the CNI's actual packet filtering behavior.
  - Functional metrics scraping end-to-end.
  - The RBAC change itself (the operator gaining `get`/`list`/`watch` on
    `networkpolicies`, `namespaces` and `pods`). It is not independently
    observable from outside the cluster role and is exercised implicitly by
    every assertion here succeeding.
  - Multiple `StorageBasedRemediationConfig` CRs with overlapping
    `nodeSelector`s, which is unsupported today.
    This test uses a single SBRC with a non-matching `nodeSelector`
    specifically to avoid that interaction while still exercising the full
    reconcile path.

## 5. Preconditions

1. SBR operator is installed via OLM and its controller-manager deployment is
   Ready.
2. An RWX-capable StorageClass exists
3. No pre-existing `test-sbrc-network-policy` SBRC, agent DaemonSet, or
   `NetworkPolicy` is left over from a previous run — `BeforeAll` deletes any
   and waits for full garbage collection before the spec creates a fresh one.

## 6. Test steps

| #  | Step (`By` text)                                                                                        | Expected result                                                                                                                      |
| -- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 1  | Creating a StorageBasedRemediationConfig with a non-matching nodeSelector so the agent DaemonSet renders without scheduling pods | `StorageBasedRemediationConfig` `test-sbrc-network-policy` is created successfully.                                                   |
| 2  | Verifying the NetworkPolicy sbr-agent-\<name\> exists for the StorageBasedRemediationConfig               | `NetworkPolicy` `sbr-agent-test-sbrc-network-policy` exists in `medik8sparams.OperatorNs` within `sbrparams.SBRCReadyTimeout`.         |
| 3  | Verifying the NetworkPolicy is owned by the StorageBasedRemediationConfig CR                               | `metadata.ownerReferences` has exactly one controlling entry, kind `StorageBasedRemediationConfig`, name matching the SBRC.          |
| 4  | Verifying the NetworkPolicy selects the agent pods for this StorageBasedRemediationConfig                  | `spec.podSelector.matchLabels` is exactly `{app: sbr-agent, sbrconfig: test-sbrc-network-policy}`.                                    |
| 5  | Verifying the NetworkPolicy restricts both ingress and egress                                              | `spec.policyTypes` is exactly `[Ingress, Egress]`.                                                                                    |
| 6  | Verifying ingress is limited to the two metrics ports, scoped to namespaces labeled metrics: enabled       | Exactly one ingress rule; ports `8080/TCP` then `8082/TCP`; `from` is exactly one `namespaceSelector` matching `metrics: enabled`, no `podSelector`/`ipBlock`. |
| 7  | Verifying egress is intentionally left unrestricted (allow-all, documented design decision)                 | Exactly one egress rule with empty `to` and `ports`.                                                                                  |
| 8  | Deleting the NetworkPolicy and verifying the operator recreates it                                         | A new `NetworkPolicy` with the same name and a different UID exists within `sbrparams.NetworkPolicyRecreateTimeout`.                 |
| 9  | Manually widening the ingress rule and verifying reconciliation restores the namespace-scoped restriction  | After the ingress `from` is cleared, the next reconcile overwrites the drift and the namespace-scoped rule is restored.               |
| 10 | Verifying the operator warns when the OpenShift monitoring namespace lacks the metrics label                | A `Warning` event with reason `MetricsNamespaceLabelMissing`, referencing `openshift-monitoring`, appears on the SBRC. Recorded as a report entry (not asserted) instead when the namespace does not exist or already carries the label. |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1970")` runs and passes.
- `NetworkPolicy` `sbr-agent-test-sbrc-network-policy` exists, is owned by the
  SBRC, and selects only its agent pods.
- Ingress is scoped to exactly the two metrics ports, reachable only from
  namespaces labeled `metrics: enabled`; egress is the single documented
  allow-all rule.
- A deleted `NetworkPolicy` is recreated, and a manually widened ingress rule
  is restored to its namespace-scoped form, both within
  `sbrparams.NetworkPolicyRecreateTimeout`.
- On a cluster where `openshift-monitoring` lacks the metrics label, 
  the SBRC receives a `MetricsNamespaceLabelMissing` warning event.
- Cleanup finishes: the test SBRC, its agent DaemonSet, and its
  `NetworkPolicy` are all gone.

## 8. Failure / known issues

None.

## 9. Cleanup

- `DeferCleanup` deletes the `test-sbrc-network-policy` SBRC and waits 
  for its agent DaemonSet and `NetworkPolicy` to be garbage-collected.
- `BeforeAll` removes any same-named leftovers from a previous run before the
  `It` creates a fresh SBRC; it creates no resource of its own.
- No node, pod, or other cluster-wide state is touched, so no additional
  recovery steps apply.

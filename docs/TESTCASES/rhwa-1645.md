## 2. Summary

Verify that the SNR operator correctly manages the `NetworkPolicy` for agent pods,
including its automatic creation, ownership by the configuration CR, recreation
upon manual deletion, and stable management of DNS-derived egress rules.
Specifically, ensure that `EndpointHealthCheckUrl` is correctly resolved to IP
CIDRs and added as `ipBlock` egress rules.

## 3. Scope

- **In scope**:
  - Automatic rendering and application of the `self-node-remediation-ds-np`
    `NetworkPolicy`.
  - OwnerReference linkage to the `SelfNodeRemediationConfig` CR.
  - Detection and recovery from `NetworkPolicy` deletion.
  - Correctness of the static ingress and egress rules (peer hostPort, DNS,
    HTTPS, own-node kubelet check).
  - Correctness and stability of the dynamic `ipBlock` egress rule derived from
    `EndpointHealthCheckUrl`, including a simulated DNS flip and
    successive changes (sole-writer stability / race coverage).

- **Out of scope**:
  - Validating the CNI's actual packet filtering behavior.
  - Remediation triggers based on the `EndpointHealthCheckUrl` health check
    itself (covered by separate SNR remediation E2E tests, e.g.
    `master_remediation.go`/`worker_remediation.go`).
  - The control-plane agent's own best-effort `NetworkPolicy` patch path
    (`internal/controlplane.Manager.ensureEndpointNetworkPolicyUpToDate` in the
    operator), which activates when the agent's own health-check ping fails.
  - Multi-address resolution: the test uses IP literals that resolve to a single
    `/32`, so the multi-`ipBlock` rendering path is not exercised.

## 6. Test steps

| # | Step (`By` text)                                                                                   | Expected result                                                                                                     |
| - | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 1 | Verifying the NetworkPolicy self-node-remediation-ds-np exists for the default SelfNodeRemediationConfig | `NetworkPolicy` `self-node-remediation-ds-np` exists in `medik8sparams.OperatorNs`.                                   |
| 2 | Verifying the NetworkPolicy is owned by the SelfNodeRemediationConfig CR                               | `metadata.ownerReferences` has exactly one entry, kind `SelfNodeRemediationConfig`, name `self-node-remediation-config`. |
| 3 | Verifying the NetworkPolicy's static ingress and egress rules                                          | Ingress allows peer agent pods on `spec.hostPort`/TCP only; egress has exactly 4 rules: peer (hostPort/TCP), DNS (53 and 5353, UDP+TCP), HTTPS (443 and 6443, TCP), and the own-node kubelet check (10250, TCP). |
| 4 | Deleting the NetworkPolicy and verifying the operator recreates it                                     | A new `NetworkPolicy` with the same name and a different UID exists within `medik8sparams.DefaultTimeout`.           |
| 5 | Setting EndpointHealthCheckUrl and verifying the egress ipBlock rule resolves to its IP                | Egress gains exactly one bare `ipBlock` rule scoped to the resolved `/32` CIDR; no unrestricted allow-all rule appears. |
| 6 | Verifying the four static egress rules survive alongside the new ipBlock rule                           | Total egress is now exactly `snrparams.NetworkPolicyStaticEgressRules + 1` (5): the four static rules are all still present and correct, plus the one `ipBlock` rule. Adding the dynamic rule must not drop or mangle a static one. |
| 7 | Simulating a DNS flip and verifying the egress ipBlock rule updates to the new IP                      | The `ipBlock` rule's CIDR updates to the newly resolved address; still exactly one such rule.                        |
| 8 | Validating NetworkPolicy stability under rapid EndpointHealthCheckUrl changes (race test)               | After `snrparams.NetworkPolicyRaceIterations` rapid alternating patches, the egress `ipBlock` rule converges on the last-applied address and remains that single rule, unchanged, for `snrparams.NetworkPolicyStabilityWindow` — no flip-flopping and no race-induced clobbering. |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1645")` runs and passes.
- The `NetworkPolicy` `self-node-remediation-ds-np` exists, is owned by the
  default `SelfNodeRemediationConfig`, and carries the static ingress/egress
  rules described above.
- A manually deleted `NetworkPolicy` is recreated within
  `medik8sparams.DefaultTimeout`.
- The `ipBlock` egress rule tracks `EndpointHealthCheckUrl` resolution
  correctly, including across a simulated DNS flip.
- Under rapid `EndpointHealthCheckUrl` changes, the egress `ipBlock` rule
  converges to the final value and then holds steady — exactly one rule, no
  allow-all fallback — for the entire `snrparams.NetworkPolicyStabilityWindow`.
- Cleanup finishes: `spec.endpointHealthCheckUrl` on the default
  `SelfNodeRemediationConfig` is restored to its pre-test value (or cleared, if
  it was unset before the test ran).

## 8. Failure / known issues

- **Two writers of the `ipBlock` rule (benign).** On control-plane nodes the SNR
  agent's `isEndpointAccessible()` fails for the unreachable TEST-NET endpoint and
  invokes `ensureEndpointNetworkPolicyUpToDate`, which patches the same
  `NetworkPolicy` the config-controller owns. Because both writers resolve the
  same `EndpointHealthCheckUrl` to the same CIDR, they converge on an identical
  `ipBlock` rule, so the stability window (step 8) still settles on exactly one
  rule.

## 9. Cleanup

- `AfterAll` restores `spec.endpointHealthCheckUrl` on the default
  `SelfNodeRemediationConfig` to the value captured in `BeforeAll`, via the
  same merge-patch mechanism used by the test. This runs even when the `It` failed
  mid-way, since it is registered in `AfterAll`, not `DeferCleanup`.
- No `DeferCleanup` is used: the test only patches the pre-existing singleton
  `SelfNodeRemediationConfig` and deletes/lets-the-operator-recreate the
  pre-existing `NetworkPolicy`; neither is a resource the test itself owns the
  lifecycle of.
- No node, pod, or other cluster-wide state is touched, so no additional
  recovery steps apply.

## 2. Summary

The SBR controller must render the agent DaemonSet with no liveness probe and no startup
probe, and with no probe of any kind that reads the host process table. A kubelet-driven
restart of a healthy agent releases the watchdog, and the replacement cannot complete
pre-flight while the node is cut off from shared storage, so a node its peers have already
fenced can be left running with nothing able to reboot it.

## 3. Scope

- **In scope**: the probe contract of the agent container in the DaemonSet the controller
  renders — `livenessProbe` and `startupProbe` absent, no `/proc`, `grep` or `cmdline` in
  any probe command, the readiness probe command and its tuning (`60/10/5/6/1`), `hostPID`
  still set, and the detect-only variant of the readiness command.
- **Out of scope**: the runtime consequences of the contract. That a healthy agent survives
  process churn, that a genuinely dead agent still restarts because it is the container
  `ENTRYPOINT`, that the watchdog reboots a node whose agent stops petting, and that a
  storage-partitioned node still self-fences are behavioural properties covered by the
  destructive specs (`block_storage_transient_partition.go`, `storage_loss_watchdog.go`,
  `block_storage_split_brain.go`, `node_hang.go`) and by the manual scenario attached to the
  bug, RHWA-1955. Block volume mode is also out of scope: the fix is mode-independent and only
  the watchdog path inside the readiness command differs (`/host-dev/watchdog`), which the
  `block_storage_*` specs already exercise on real agents.

| Platform     | `platform:any`                                                  |

Environment variables:

```bash
export KUBECONFIG=/absolute/path/to/kubeconfig
export ECO_TEST_FEATURES=sbr-operator
export ECO_TEST_LABELS='operator:sbr && tier:smoke'
export WORKLOAD_IMAGE=registry.access.redhat.com/ubi9/ubi-minimal:latest
# Optional: skip CephFS auto-discovery and name the RWX class directly.

```

`SBR_STORAGE_CLASS` defaults to empty. When unset, `discoverRWXStorageClass` looks for a
StorageClass with a CephFS provisioner and `Skip`s the spec with an actionable message when
it finds none.

## 5. Preconditions

1. The SBR operator is installed in `openshift-workload-availability` and its
   controller-manager is reconciling.
2. An RWX StorageClass exists, or `SBR_STORAGE_CLASS` names one. `BeforeAll` resolves it
   and the spec skips when neither is available.
3. No `StorageBasedRemediationConfig` named `test-sbrc-probe-shape` is left over from a
   previous run. `BeforeAll` deletes it and waits for both the CR and its DaemonSet to be
   fully gone before the spec recreates them.
4. No node carries the label `sbr-test-no-match-selector=sbr-test-no-match-value`. The
   spec asserts `desiredNumberScheduled == 0`, which fails loudly if one does.

## 6. Test steps

| #  | Step (`By` text) | Expected result |
| -- | ---------------- | --------------- |
| 1  | `Discovering an RWX-capable StorageClass, which the controller requires before it renders the agent DaemonSet` | A class name is resolved from `SBR_STORAGE_CLASS` or CephFS auto-discovery; otherwise the spec skips |
| 2  | `Deleting any probe-contract SBRC left behind by a previous run` | The stale config is deleted or already absent; an unexpected error is logged, not fatal |
| 3  | `Waiting for the stale SBRC and its DaemonSet to be fully gone` | `test-sbrc-probe-shape` returns `IsNotFound` and `sbr-agent-test-sbrc-probe-shape` is garbage-collected |
| 4  | `Creating a StorageBasedRemediationConfig whose nodeSelector matches no node` | The config is admitted by the API server |
| 5  | `Waiting for the controller to render the agent DaemonSet without scheduling agent pods` | `sbr-agent-test-sbrc-probe-shape` exists within `sbrparams.SBRCReadyTimeout` with `status.desiredNumberScheduled == 0` |
| 6  | `Asserting the agent container carries no liveness and no startup probe` | `livenessProbe` and `startupProbe` on the `sbr-agent` container are both `nil` |
| 7  | `Asserting no agent probe scans the host process table` | No exec command of any probe contains `/proc`, `grep`, or `cmdline` |
| 8  | `Asserting the readiness probe checks the pre-flight sentinel and the watchdog device` | The readiness command is exactly `/bin/sh -c "test -f /var/run/sbr-agent/preflight-ok && test -c /dev/watchdog"` |
| 9  | `Asserting the readiness probe tuning is unchanged` | `initialDelaySeconds 60`, `periodSeconds 10`, `timeoutSeconds 5`, `failureThreshold 6`, `successThreshold 1` |
| 10 | `Asserting the agent pod template still sets hostPID` | `spec.template.spec.hostPID` is `true` |
| 11 | `Patching the StorageBasedRemediationConfig into detect-only mode` | The patch is accepted and the DaemonSet generation advances past the pre-patch value |
| 12 | `Asserting detect-only readiness drops the watchdog check and adds no other probe` | The readiness command is exactly `/bin/sh -c "test -f /var/run/sbr-agent/preflight-ok"`, and liveness and startup are still `nil` with no process-table scan |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1965")` runs and passes.
- The agent container of `sbr-agent-test-sbrc-probe-shape` has `LivenessProbe == nil` and
  `StartupProbe == nil` in both remediation and detect-only mode.
- No probe command on that container contains any of `/proc`, `grep`, `cmdline`.
- The readiness probe command and its five tuning fields equal the values in steps 8, 9
  and 12.
- `hostPID` is `true`, which is the reason a process-table probe self-matches and must not
  come back.
- Cleanup finishes: `DeferCleanup` deletes the config and the DaemonSet is garbage-collected
  within `sbrparams.SBRCDaemonSetGCTimeout`, leaving the namespace as it was found.

## 8. Failure / known issues

None.

The spec is not gated: it passes on any build carrying the RHWA-1955 fix, which is every
build from storage-based-remediation PR #151 onwards.

On a pre-fix build the spec fails at step 6 with the liveness and startup probes present and
at step 7 with all three commands containing `grep -l sbr-agent /proc/*/cmdline`. That is the
intended regression signal, not a known issue.

## 9. Cleanup

- `DeferCleanup` deletes the `test-sbrc-probe-shape` config the `It` created and waits for
  `sbr-agent-test-sbrc-probe-shape` to be garbage-collected, tolerating `IsNotFound` and
  logging a warning with `GinkgoT().Logf` rather than failing.
- `AfterAll` removes nothing: `BeforeAll` creates no resource, it only deletes stale ones.
- No recovery step is needed. The spec schedules no agent pod, injects no fault and changes
  no node, so a mid-way failure leaves only the config, which `DeferCleanup` removes.
- The shared-storage PVC and SBD device-init Job the controller creates are removed by the
  operator's own cleanup when the config is deleted.

## 12. Implementation sketch

Implemented in
[`tests/sbr-operator/tests/agent_probes.go`](../../tests/sbr-operator/tests/agent_probes.go).
The spec creates one config whose `nodeSelector` matches no node, so the controller renders
the agent pod template in full while scheduling zero agent pods. The probe contract lives in
that template, so the assertions need no running agent and disturb no node:

```go
It("Verify the sbr-agent DaemonSet carries no liveness or startup probe and no probe "+
    "scans the host process table",
    reportxml.ID("1965"),
    func() {
        agentDS := getAgentDaemonSet(sbrparams.SBRCProbeShapeTestName)
        container := getAgentContainer(agentDS)

        assertNoLivenessOrStartupProbe(container, "remediation mode")
        assertNoProcessTableProbe(container)
    })
```

## 2. Summary

Verify that filesystem-mode SBR agents remove the temporary heartbeat written to
slot 1 during startup when no real node owns that ID. Agents must stay Ready
without restarts while the unused slot is observed.

## 3. Scope

- **In scope**: RHWA-1058, the unused preflight slot after hash-based assignment,
  node-map ownership, and agent stability.
- **Out of scope**: RHWA-1056 deletion/recreation cleanup, covered by
  `node_map_cleanup.go` in PR #69. Block storage, remediation, reboot behavior,
  legitimate ownership of ID 1, and historical-build deployment are not covered.
  The test skips when a real agent owns ID 1, because that run cannot exercise
  the unused-slot regression. Peer-log content and delivery are outside this
  test's pass criteria.

## 4. Environment

| Requirement | Value |
| --- | --- |
| Cluster | OpenShift with at least two Ready, schedulable workers |
| Topology | `topology:minimal-worker` |
| Platform | `platform:any` |
| Storage | RWX filesystem storage, CephFS auto-discovered or `SBR_STORAGE_CLASS` |
| Network | Connected or disconnected with operator images already available |
| Namespace | `openshift-workload-availability` |
| Destructive? | No fault injection, fencing, or node reboot |

The existing runner reads `KUBECONFIG`, `ECO_TEST_FEATURES`, `ECO_TEST_LABELS`,
`ECO_TEST_FOCUS`, and `WORKLOAD_IMAGE`. The last is required by suite initialization
but not used by this test. `SBR_STORAGE_CLASS` selects an existing RWX class. When
unset, the shared helper discovers CephFS and skips if none is available. No new
environment variables are introduced.

## 5. Preconditions

`BeforeAll` checks, in order:

1. SBR's controller deployment is Ready. Its container images are reported.
2. No NodeHealthCheck references an SBR remediation template. Skip otherwise.
3. No SNR agent DaemonSet or agent pods remain. Stop SNR externally before running,
   preserving its configuration for restoration afterward.
4. Any leftover SBRC carrying this test's label is deleted with its operands.
   Unrelated SBRCs are never deleted, and cause a skip.
5. At least two workers are Ready and schedulable, and RWX storage is available.

## 6. Test steps

| # | Step (`By` text) | Expected result |
| --- | --- | --- |
| 1 | Verifying SBR is Ready | Ready controller, recorded image |
| 2 | Verifying no NodeHealthCheck remediates through the SBR template | No automatic SBR fencing |
| 3 | Verifying SNR agents are stopped | No watchdog contention |
| 4 | Removing only this test's stale configurations | Previous test resources gone, no unrelated SBRC |
| 5 | Checking worker and RWX storage prerequisites | At least two workers and a selected storage class |
| 6 | Creating a filesystem SBRC and waiting for all agents | Ready agents on distinct nodes |
| 7 | Verifying slot 1 has no real owner in the shared node map | Valid CRC and one unique mapping per agent node, ID 1 unused |
| 8 | Observing the unused slot and agent stability for one minute | Every agent reads exactly 512 zero bytes at offset 512, same pods and restart counts |
| 9 | Removing the test configuration and waiting for its operands | SBRC, agent DS, labeled jobs, pods and PVCs gone |

## 7. Pass criteria

- Exactly one spec with `reportxml.ID("1964")` runs and passes.
- All agents are Ready within `sbrparams.SBRCReadyTimeout`.
- The checksummed node map identifies every agent node with a unique ID in 1-255.
  ID 1 is unassigned. Legitimate ownership skips the spec rather than passing it.
- For `sbrparams.GhostPeerObservationDuration`, all agents stay Ready with the
  same pod UIDs and restart counts. The full filesystem heartbeat slot 1 is zero
  through every agent. Missing/short reads fail the test.
- Cleanup finishes within `sbrparams.GhostPeerCleanupTimeout`.

## 8. Failure / known issues

[RHWA-1058](https://redhat.atlassian.net/browse/RHWA-1058) was addressed by
[product PR #69](https://github.com/medik8s/storage-based-remediation/pull/69).
A pre-fix build leaves a nonzero heartbeat in the unassigned slot and can log a
phantom peer. This PR validates the installed fixed build, not an old/new image
comparison. There is no known failure gate for the fixed build.

Original live validation on 2026-10-26 against SBR v5.8.0: one passed spec, three Ready
agents, empty slot 1 for one minute, and no agent restarts during observation.
Test resources were removed, SNR restored to 6/6 Ready with its original
configuration, and all six nodes remained Ready. No pre-fix comparison was run.

## 9. Cleanup

`DeferCleanup` deletes only the generated test SBRC, using a UID precondition.
It waits for normal operator cleanup, then removes remaining jobs for that exact
configuration with background propagation, and waits for the SBRC, DS, pods,
jobs and PVCs to disappear. Missing resources are tolerated. Operator finalizers
are never stripped. Cleanup runs on failure and skip as well as success.
`BeforeAll` uses the same cleanup for leftovers carrying the dedicated test label.
No `AfterAll` resources or recovery from injected faults are needed.
The test does not change SNR. The live runner must restore its saved configuration
after SBR cleanup if SNR was stopped for the run.

## 11. Running it standalone

On a cluster satisfying the preconditions:

```bash
export KUBECONFIG=/absolute/path/to/kubeconfig
export WORKLOAD_IMAGE=unused-by-sbr-ghost-peer
export ECO_TEST_FEATURES=sbr-operator
export ECO_TEST_LABELS='operator:sbr && tier:acceptance'
export ECO_TEST_FOCUS='startup clears the unassigned preflight slot'
make run-tests
```

Equivalent Ginkgo selection:

```bash
ginkgo -v --label-filter='operator:sbr && tier:acceptance' \
  --focus='startup clears the unassigned preflight slot' ./tests/sbr-operator
```

## 12. Implementation sketch

Implementation: [ghost_peer.go](../../tests/sbr-operator/tests/ghost_peer.go).

One ordered, serial spec creates an SBRC and registers cleanup immediately.
Existing storage discovery, readiness, NHC preflight, and checksummed node-map
parsing helpers are reused. Private helpers in `ghost_peer.go` inspect agents,
read the filesystem slot, and clean up this test's resources.
No shared framework or new helper files are required.
